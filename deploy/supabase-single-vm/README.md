# Платформа ИКР: свой Supabase на одной машине (Selectel)

Выбранная схема размещения: одна машина, на ней Supabase в Docker (только нужные сервисы) и приложение ИКР.
Файлы — в S3-совместимом хранилище (любом: адрес и ключи в `.env`). В Selectel пока ничего не создано.
Сборка проверена локально (13.10.2026) на тех же версиях образов; S3 подменялся эмулятором.

## Что внутри

| Сервис | Образ | Роль | Память без нагрузки |
|---|---|---|---|
| `db` | `supabase/postgres:17.6.1.136` | PostgreSQL 17 с ролями Supabase, схемами `auth` и `storage` | ~90 МБ (предел 1 ГБ) |
| `auth` | `supabase/gotrue:v2.196.0` | Вход: пароли, сессии, блокировка. Регистрация закрыта, TOTP выключен (у ИКР свой код на почту) | ~12 МБ |
| `rest` | `postgrest/postgrest:v14.17` | API к таблицам схемы `public`. Служебные схемы не публикуются | ~19 МБ |
| `storage` | `supabase/storage-api:v1.74.0` | Файлы. Сами файлы — в любом S3 из `.env` | ~115 МБ |
| `gateway` | `caddy:2.10.2-alpine` | HTTPS (Let's Encrypt), маршруты, проверка ключа `apikey` | ~14 МБ |

**Не включено:**
- Studio (панель управления);
- Realtime, Edge Functions, imgproxy, аналитика, Supavisor;
- Kong и Envoy — их заменяет Caddy.

**Доступ снаружи:**
- открыты только порты 80 и 443;
- база снаружи недоступна.

Посмотреть данные можно через SSH: `docker compose exec db psql -U postgres`.

**Образы занимают ~3,2 ГБ на диске.**

## Что проверено локально

1. `/rest/v1` без ключа или с чужим ключом — 401, с ключом anon — 200.
2. Регистрация закрыта (`signup_disabled`).
3. Приглашение без почты:
   - `POST /auth/v1/admin/generate_link` (ключ service_role) возвращает ссылку;
   - по ней человек входит один раз;
   - повторный переход — `otp_expired`.
4. Вход по паролю.
5. RLS:
   - пользователь A видит свою запись;
   - пользователь B и аноним — пустой список.
6. Служебная схема `auth` через API недоступна (`PGRST106`).
7. Файлы:
   - закрытый бакет лежит в S3;
   - без входа и через «публичную» ссылку — отказ;
   - подписанная ссылка на 60 с — 200.
8. `backup-db.sh`:
   - копия зашифрована, выгружена и сверена по размеру;
   - копия 20-дневной давности удалена, 5-дневной — оставлена, посторонний файл не тронут.
9. `restore-check.sh`:
   - восстановление во временный контейнер;
   - пользователи, таблицы и записи о файлах совпали с копией;
   - временный контейнер удалён.
10. `update.sh`: копия перед обновлением, перезапуск, все сервисы «healthy».

## Установка (когда будет разрешение)

1. Docker Engine и плагин compose из официального репозитория Docker для Ubuntu 24.04.
2. `install -d -m 0750 /opt/ikr-supabase`, затем скопировать туда эту папку.
3. `cp .env.example .env`, вписать домен и ключи S3, затем `bash scripts/gen-keys.sh /opt/ikr-supabase/.env`. Пароли и ключи создаются на сервере, на экран не выводятся.
4. `docker compose up -d`, затем `docker compose ps` — все сервисы «healthy».
5. `/etc/ikr-supabase/backup.env` по шаблону `backup.env.example` (права 600). Закрытый ключ age хранится у владельца, не на сервере.
6. Таймер копий: `cp systemd/* /etc/systemd/system/`, затем `systemctl enable --now ikr-supabase-backup.timer`.
7. Пробное восстановление: `bash scripts/restore-check.sh /root/age.key`. После проверки ключ удалить с сервера.

## Платформа ИКР на этой сборке

Платформа ИКР проверена на этой сборке без изменений кода:
- миграции и демо-данные применились;
- pgTAP — 157 из 157;
- e2e входа — 12 из 12;
- загрузка резюме с сайта уходит в S3.

Условия:
- сайт и Supabase — на одном домене (так настроен `Caddyfile`), иначе браузер не загрузит резюме: Storage не отвечает на CORS;
- `SUPABASE_URL` приложения — публичный адрес `https://<домен>`;
- `APP_UPSTREAM` — `host.docker.internal:3000`.
