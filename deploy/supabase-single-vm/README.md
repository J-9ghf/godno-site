# Платформа ИКР: свой Supabase на одной машине (Selectel)

Выбранная схема размещения: одна машина Ubuntu 24.04 (2 vCPU / 4 ГБ / 40 ГБ), на ней Supabase в Docker
(только нужные сервисы) и приложение ИКР как служба systemd. Файлы — в S3-совместимом хранилище (любом:
адрес и ключи в `.env`). Копии базы — в отдельный бакет S3, зашифрованные age, хранятся 14 дней.

Инструкции для владельца: [`docs/DEPLOY-SELECTEL.md`](../../docs/DEPLOY-SELECTEL.md) (установка),
[`docs/RESTORE.md`](../../docs/RESTORE.md) (восстановление).

## Сервисы

| Сервис | Образ | Роль | Память без нагрузки |
|---|---|---|---|
| `db` | `supabase/postgres:17.6.1.136` | PostgreSQL 17 с ролями Supabase, схемами `auth` и `storage` | ~90 МБ (предел 1 ГБ) |
| `auth` | `supabase/gotrue:v2.196.0` | Пароли, сессии, блокировка. Регистрация закрыта, TOTP выключен (у ИКР свой код второго шага) | ~15 МБ |
| `rest` | `postgrest/postgrest:v14.17` | API к таблицам схемы `public` (запросы приложения через supabase-js) | ~30 МБ |
| `storage` | `supabase/storage-api:v1.74.0` | Файлы; сами файлы — в S3 из `.env` | ~120 МБ |
| `gateway` | `caddy:2.10.2-alpine` | HTTPS (Let's Encrypt), один домен для сайта и Supabase, проверка `apikey`, маскировка токенов в журнале | ~30 МБ |
| приложение | Next.js, служба `ikr-app` (порт 3000, снаружи закрыт) | сайт и кабинеты | ~200 МБ |

Не включено: Studio, Realtime, Edge Functions, imgproxy, аналитика, Supavisor, Kong.
Снаружи открыты только 22, 80 и 443; база наружу не публикуется. Образы занимают ~3,2 ГБ.

Сайт и `/storage/v1` обязательно на одном домене: браузер загружает резюме прямо в Storage, а Storage
не отвечает на CORS. Caddy так и настроен.

## Файлы

| Файл | Что делает |
|---|---|
| `docker-compose.yml`, `Caddyfile`, `volumes/db/*.sql` | сервисы, шлюз, роли базы |
| `.env.example`, `backup.env.example` | шаблоны настроек (секретов нет, только заполнители) |
| `scripts/install.sh` | установка на новую машину целиком: пакеты, брандмауэр, ключи, запуск, миграции, приложение, копии, проверка. Повторный запуск безопасен |
| `scripts/gen-keys.sh` | пароль базы и ключи JWT — на сервере, без вывода на экран |
| `scripts/migrate.sh` | миграции `supabase/migrations` (учёт в `supabase_migrations.schema_migrations`, копия перед новыми); демо-данные — только с `--demo` |
| `scripts/create-admin.sh` | приглашение первого администратора: ссылка на 72 часа показывается один раз, в базе только хэш |
| `scripts/login-code.sh` | код второго шага админа из журнала, пока почта не подключена |
| `scripts/backup-db.sh`, `systemd/ikr-supabase-backup.*` | ночная копия: дамп и подсчёт записей из одного снимка базы, age, S3, сверка размера, хранение 14 дней, копия файлов |
| `scripts/restore-check.sh` | проверка копии во временном контейнере (рабочая база не затрагивается) |
| `scripts/restore-db.sh` | восстановление рабочей базы: выбор копии, страховочная копия, пересоздание базы, сверка, проверка сайта |
| `scripts/update-app.sh` | обновление приложения: копия, миграции, сборка в отдельной папке, замена, проверка |
| `scripts/update.sh` | обновление образов Supabase с копией перед ним |
| `scripts/health.sh` | проверка: главная, вход, Auth и связь приложения с Supabase |
| `systemd/ikr-app.service` | служба приложения (пользователь `ikr`, настройки в `/etc/ikr/app.env`) |

## Что проверено (13.10.2026, локальный стенд Ubuntu 24.04, S3 — эмулятор)

- `install.sh` с нуля: все шаги, повторный запуск не меняет пароли и ключи, файлы с ключами — 600, root.
- pgTAP 157 из 157 (миграции применены `migrate.sh` от роли `postgres`, как в облачном Supabase).
- e2e 22 из 22 через Caddy (`E2E_VIA_PROXY=1`): вход, приглашения, второй шаг админа, отключение, автовыход,
  выход на публичный адрес, лимит по настоящему адресу клиента, загрузка резюме в S3.
- Копия во время записи в базу → проверка восстановления без расхождений.
- `restore-db.sh` на той же машине и на заново установленной с новыми ключами → e2e 22 из 22, пароли пользователей прежние.
- `create-admin.sh` → первый админ задаёт пароль, входит с кодом; ссылка повторно не открывается.
- `update-app.sh` → сборка в отдельной папке и замена работают.
- В журнале Caddy токены приглашений и сброса пароля заменены на `***`.

**Не проверено на настоящей машине Selectel:** установка пакетов и брандмауэра, служба systemd, выпуск
сертификата Let's Encrypt, доступ к Docker Hub и S3 Selectel. Это первое, что проверяется при установке.
