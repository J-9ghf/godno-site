# Платформа ИКР — кабинеты клиента и администратора

Сервер, база данных и вход. Экраны кабинетов из демоверсии (`../prototypes/ikr-platform.html`) подключаются на этапе 6.
Архитектура и решения: `../docs/platform/`.

## Стек

Astro 7 в серверном режиме (Node 22) · PostgreSQL 16 · Better Auth 1.7 · pdf.js для проверки PDF · S3-совместимое хранилище (Yandex Object Storage) или локальная папка.

## Локальный запуск без Docker

Нужны Node 22 и PostgreSQL 16 (программы `initdb`, `pg_ctl`, `psql`).

```bash
npm ci
./scripts/dev-db.sh start                      # база в .dev/pg, порт 54329, роли ikr_owner и ikr_app
cp .env.example .env                           # заполните BETTER_AUTH_SECRET (openssl rand -base64 48)
export $(grep -v '^#' .env | xargs)            # или используйте свой способ загрузки .env
npm run migrate                                # нужна DATABASE_OWNER_URL
npm run build && npm start                     # http://localhost:4321
npm run create-admin -- you@example.test       # ссылка приглашения выводится в консоль и сохраняется в .dev/mail
npm run seed:dev                               # вымышленные данные и приглашение клиента client-demo@example.test
```

Локальная база создаётся с доверительным входом (`--auth=trust`) только на 127.0.0.1 и предназначена для разработки.

Альтернатива с Docker: `docker-compose.yml` (PostgreSQL, MinIO, Mailpit). Этот файл пока не проверен.

## Тесты

```bash
npm test
```

Тесты сами поднимают временную PostgreSQL, применяют миграции, собирают и запускают сервер и проверяют его по HTTP.
Письма пишутся во временную папку, файлы хранятся во временной папке. Драйвер S3 проверяется на эмуляторе moto,
если указан путь к нему: `MOTO_SERVER=/путь/к/moto_server npm test`, иначе этот тест пропускается.

| Файл | Что проверяет |
|---|---|
| `auth.test.ts` | закрытая регистрация, приглашения (одноразовые, хэш, срок, отзыв), cookie, проверка Origin, ограничение попыток по почте и IP, сброс пароля, блокировка, сроки сессии |
| `isolation.test.ts` | клиент A не видит данных клиента B через API, подмену ID, фильтры и напрямую в базе; роли; этапы и история |
| `consent.test.ts` | представление невозможно без согласия; согласие для одного работодателя не подходит другому; отзыв согласия и представления закрывает доступ сразу |
| `files.test.ts` | проверка типа по содержимому, лимит размера, случайные ключи, просмотр и скачивание по отдельным правам, заголовки, журнал |
| `metrics.test.ts` | точные значения показателей по правилам расчёта, фильтры, обновление после смены этапа |
| `s3-driver.test.ts` | драйвер S3 на эмуляторе |

## Безопасность

- Регистрации нет. Доступ только по приглашению (`create-admin` для первого администратора, далее из API).
- Паролей и секретов в репозитории нет. Все настройки — переменные окружения (`.env.example`).
- Права проверяются на сервере и повторно в базе (RLS). Приложение подключается ролью `ikr_app` без обхода RLS.
- Клиент получает данные кандидатов только через представления `client_*` и функции базы, по ID представления.
- Файлы отдаются только сервером после проверки прав на каждый запрос, без публичных ссылок.
