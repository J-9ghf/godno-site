# ClamAV: развёртывание и проверка

ClamAV — свободный антивирус. Он работает на нашем сервере, файлы никуда не отправляются, лицензия бесплатная. Платформа отправляет каждый загружаемый файл в службу `clamd` по протоколу INSTREAM. Файл не принимается, если ClamAV:
- нашёл угрозу;
- недоступен;
- не ответил вовремя;
- отказался проверять файл, например из-за превышения лимита.

## Установка (Ubuntu 24.04, тот же сервер или отдельная ВМ в той же сети)

```bash
sudo apt-get install -y clamav-daemon clamav-freshclam
sudo systemctl enable --now clamav-freshclam   # обновление баз сигнатур, по умолчанию раз в час
sudo systemctl enable --now clamav-daemon
```

Настройки `/etc/clamav/clamd.conf`, которые нужно проверить:

```
TCPSocket 3310
TCPAddr 127.0.0.1          # или внутренний адрес; порт закрыт для интернета
StreamMaxLength 25M        # больше MAX_UPLOAD_MB платформы (15 МБ)
MaxFileSize 25M
MaxScanSize 100M
ScanPDF yes
```

Настройки платформы:

```
FILE_SCAN_MODE=clamav
CLAMAV_HOST=127.0.0.1
CLAMAV_PORT=3310
```

Базам сигнатур нужен доступ к `database.clamav.net` или к своему зеркалу. Для `clamd` нужно около 1,5 ГБ памяти.

## Проверка перед приёмом файлов кандидатов

1. Ответ службы: `printf 'zPING\0' | nc 127.0.0.1 3310` → `PONG`. Версия: `printf 'zVERSION\0' | nc 127.0.0.1 3310` — дата баз не старше суток.
2. Автотесты с настоящим ClamAV:
   ```bash
   CLAMAV_TEST_HOST=127.0.0.1 CLAMAV_TEST_PORT=3310 npm test -- tests/clamav-real.test.ts
   ```
   Тесты проверяют:
   - чистый PDF принимается;
   - PDF с тестовой строкой EICAR и с тестовым маркером отклоняется, не сохраняется и записывается в журнал;
   - при недоступном ClamAV загрузка отклоняется;
   - повторная проверка отправляет заражённый файл в карантин.

   Тестовый маркер `IKR-MALWARE-TEST-MARKER-7f3a` ловит своя сигнатура. Её нужно положить в каталог баз только на время проверки:
   ```bash
   echo "Test.IKR.PdfMarker:0:*:$(printf 'IKR-MALWARE-TEST-MARKER-7f3a' | od -An -tx1 | tr -d ' \n')" | sudo tee /var/lib/clamav/ikr-test.ndb
   printf 'zRELOAD\0' | nc 127.0.0.1 3310
   ```
   После проверки файл `ikr-test.ndb` удалить и снова выполнить `zRELOAD`.
3. Необязательно: второй `clamd` с `StreamMaxLength 1M` на другом порту (`CLAMAV_TEST_SMALL_PORT`). Он проверяет, что слишком большой для ClamAV файл не считается чистым.
4. Вручную через кабинет: загрузить тестовый файл EICAR, вложенный в PDF. Должно появиться сообщение «Файл не прошёл антивирусную проверку», а в журнале — запись `file.rejected_infected`.
5. Если файлы загружались при выключенной проверке, проверить их заново:
   ```bash
   npm run rescan-files -- --as admin@example.ru         # файлы «не проверен» и «ошибка»
   npm run rescan-files -- --as admin@example.ru --all    # все файлы, например после обновления баз
   ```
   Заражённый файл получает статус `infected` и уходит в карантин:
   - клиенты и администраторы его не открывают;
   - выбрать его для клиента нельзя.
   Все изменения записываются в журнал.

## Наблюдение

- Следить за работой `clamav-daemon` и `clamav-freshclam` и за возрастом баз. Если базы старше 2 суток — тревога.
- Ошибки проверки (`scan_unavailable`) видны пользователю и в журнале сервера. Если их много, ClamAV недоступен, и файлы в это время не принимаются.
- Раз в неделю запускать `rescan-files --all`: файлы перепроверяются по новым сигнатурам.

## Что проверено локально (этап 7)

- Настоящий ClamAV 1.5.4 (`clamd`) запускался в среде разработки.
- Официальные базы скачать не удалось: сетевая политика среды разработки не пускает к `database.clamav.net`. Поэтому `clamd` работал со своей тестовой базой: сигнатура EICAR и тестовый маркер.
- Это проверка развёртывания и связки «платформа — clamd», а не охвата реальных угроз.
- На рабочем сервере проверку нужно повторить с официальными базами.
