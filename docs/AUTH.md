# Вход, приглашения и доступы (этап 2)

## Как устроено

| Требование | Как сделано |
|---|---|
| Нет открытой регистрации | В Auth выключено (`enable_signup = false`). Пользователя создаёт только сервер, когда человек открывает приглашение |
| Приглашение: одноразовое, 72 часа | Таблица `invitations`, хранится только SHA-256 токена. Ссылка «занимается» одним атомарным `update`, второй переход не сработает. CHECK в базе запрещает срок больше 72 часов |
| Пароль не короче 10 символов | Проверка на сервере (`lib/auth/validation.ts`) и в Auth (`minimum_password_length = 10`) |
| Вход не сообщает, есть ли почта | Одинаковый текст «Неверная почта или пароль.» и одинаковая блокировка для любых адресов. «Забыли пароль» всегда отвечает одинаково |
| 5 ошибок → 15 минут | `login_attempts` + `login_locked_until()`: по почте 5 ошибок, по IP 20. Успешный вход и сброс пароля обнуляют счётчик |
| Автовыход через 30 минут | `proxy.ts` на каждом запросе к `/cabinet` и `/admin` сверяет httpOnly-cookie активности. В браузере `IdleWatcher` выводит через 30 минут без действий (за минуту предупреждает) и продлевает отметку, пока человек работает. Общая длительность сессии — не больше 12 часов |
| Двойная проверка для админа | После пароля сессия не выдаётся: на почту уходит 6-значный код (10 минут, 5 попыток, повторная отправка не чаще 3 раз за 10 минут). После кода сервер записывает `session_id` в `verified_sessions`. **Права админа в RLS действуют только для подтверждённой сессии**, поэтому прямой вход в Supabase Auth в обход приложения прав админа не даёт |
| Отключение одним действием | Кнопка «Отключить» в разделе «Пользователи и доступы»: `is_active = false` (база сразу перестаёт отдавать данные), блокировка в Auth, отзыв всех сессий |
| Журнал | Входы, неудачные попытки, блокировки, коды, выходы (по кнопке и по бездействию), приглашения, сбросы пароля — в `audit_log` с IP и браузером |
| Service role только на сервере | `lib/supabase/admin.ts` с `import 'server-only'`, переменные без `NEXT_PUBLIC_`. Браузер к Supabase не обращается вообще: сессия в httpOnly-cookie, запросы идут через сервер. Проверка: `npm run check:secrets` после сборки |
| Защита маршрутов | `proxy.ts` — только вошедшие; макеты разделов — по роли (`requireRole`): `/cabinet` только клиенту, `/admin` менеджеру и админу, `/admin/users` только админу. Роль считает база (`my_access()`), с учётом отключения и второго шага |

Тексты страницы входа и письма-приглашения взяты из документа «Контент лендинга по блокам», раздел 4.

## Страницы

| Адрес | Что |
|---|---|
| `/login` | Вход для клиентов (и команды) |
| `/login/code` | Код из письма (только админ) |
| `/forgot` | Восстановление пароля |
| `/reset/[token]` | Новый пароль по ссылке из письма (1 час, одноразовая) |
| `/invite/[token]` | Приглашение: имя и пароль, затем сразу вход |
| `/admin/users` | Админ: новая компания, приглашение, список пользователей с отключением, приглашения с отзывом |
| `/cabinet`, `/admin` | Заготовки кабинетов (этапы 4 и 5) |

Приглашать коллег руководитель клиента сможет из профиля на этапе 4. Серверная логика и правило в базе уже есть.

## Запуск локально

```bash
npm install
npx supabase start            # см. docs/DB.md
npx supabase db reset         # схема + демо-данные с паролями
cp .env.example .env.local    # SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY из `npx supabase status`
npm run dev                   # http://localhost:3000/login
```

Демо-пароль у всех пользователей из `supabase/seed.sql`: `IkrDemo-2026!`. С `EMAIL_PROVIDER=console`
письма (коды, приглашения, сброс) печатаются в консоль `npm run dev`.

## Тесты

```bash
npm test                      # unit: автовыход, пароль, токены
npm run db:test               # pgTAP: 145 проверок, включая второй шаг админа
npx supabase test db          # те же pgTAP на настоящем Supabase

# e2e: приложение запущено с ящиком писем, база — локальный Supabase
EMAIL_OUTBOX_FILE=/tmp/ikr-outbox.jsonl npm run build && EMAIL_OUTBOX_FILE=/tmp/ikr-outbox.jsonl npm start
EMAIL_OUTBOX_FILE=/tmp/ikr-outbox.jsonl E2E_DB_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres npm run e2e
```

e2e (12 сценариев): закрытые разделы без входа, одинаковый ответ для чужой почты, вход клиента и запрет
кабинета команды, блокировка после 5 ошибок, код для админа, менеджер без раздела пользователей,
приглашение (короткий пароль, вход, повторная ссылка), восстановление пароля, отключение с закрытием
открытой сессии, автовыход, httpOnly-cookie.

## Что учесть при запуске на облаке

- Демо-пароль известен из репозитория. Демо-проект с `seed.sql` не публикуйте открыто: смените пароли
  или отключите демо-пользователей. В рабочую базу `seed.sql` не загружается.
- В облаке выключите регистрацию и выставьте лимиты Auth (`docs/DB.md`, раздел «Облачный проект»).
- Почта: `EMAIL_PROVIDER=smtp` и `SMTP_*`. Пока провайдер не выбран, коды админа видны только в логах сервера.
