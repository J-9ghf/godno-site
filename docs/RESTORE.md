# Как восстановить платформу ИКР из копии

Копия базы делается каждую ночь и хранится 14 дней в хранилище `ikr-backup`. Копии зашифрованы:
открыть их можно только **ключом копий** — три строки, которые вы сохранили при установке
(«ИКР — ключ копий» в менеджере паролей).

Что входит в копию: пользователи и их пароли, компании, заявки, кандидаты, приглашения, журнал действий,
записи о файлах. Сами файлы кандидатов лежат в хранилище `ikr-files` и восстановлением базы не меняются.

Выберите свой случай:

- **А.** Машина работает, но данные испорчены или удалены по ошибке.
- **Б.** Машины больше нет (удалена, сломалась) — нужна новая.

## А. Восстановить данные на той же машине

Сайт будет недоступен 5–15 минут. Всё, что появилось в базе после выбранной копии, пропадёт
(перед восстановлением скрипт сам сохранит текущее состояние — его можно будет вернуть).

1. Подключитесь к машине: `ssh root@IP-адрес` (как в шаге 4 инструкции по установке).
2. Положите ключ копий во временный файл. Вставьте команду, затем вставьте три строки ключа
   и нажмите **Enter**, потом **Ctrl+D**:

   ```
   cat > /root/backup-key.txt
   ```

3. Запустите восстановление:

   ```
   bash /opt/ikr-supabase/scripts/restore-db.sh /root/backup-key.txt
   ```

4. Скрипт покажет список копий с датой и количеством пользователей, кандидатов и заявок, например:

   ```
    13) 12.10.2026 00:30 — пользователей 41, кандидатов 380, заявок 57
    14) 13.10.2026 00:30 — пользователей 41, кандидатов 12, заявок 57
   ```

   Время указано по UTC: московское на 3 часа больше. Напишите номер копии, сделанной **до** ошибки,
   и нажмите Enter.
5. Скрипт попросит подтверждение — напечатайте `ВОССТАНОВИТЬ`.
6. В конце должно быть написано `сайт работает` и `ГОТОВО`.
7. **Удалите ключ с машины:**

   ```
   shred -u /root/backup-key.txt
   ```

Сохранённое перед восстановлением состояние лежит в `/var/backups/ikr-supabase/before-restore-…`.
Если восстановили не ту копию, напишите разработчику — состояние можно вернуть.

## Б. Восстановить на новой машине

1. Пройдите шаги 1, 4, 5 и 6 из [DEPLOY-SELECTEL.md](DEPLOY-SELECTEL.md). Отличия:
   - хранилища и ключи S3 **не создавайте заново** — используйте прежние `ikr-files` и `ikr-backup`
     (если ключ S3 потерялся — выпустите новый для того же сервисного пользователя);
   - в шаге 3 поменяйте IP-адрес в записи домена на адрес новой машины;
   - на вопрос «Создать ключ для копий?» ответьте `н` и вставьте **открытый ключ** — строку из
     сохранённого ключа после `# public key:` (начинается с `age1`).
2. Установка закончится словами `ГОТОВО`, но база будет пустой. Восстановите её по пунктам 2–7 раздела А.
   В списке копий будет и копия, которую только что сделала установка, — у неё 0 пользователей.
   **Выберите копию с данными** (обычно предпоследнюю).
3. Первого администратора создавать не нужно: все пользователи и их пароли восстановятся из копии.
   Всем придётся войти заново.

## Если пропали файлы кандидатов

Файлы хранятся в `ikr-files`, а каждую ночь их копия дополнительно складывается в `ikr-backup/files`.
Вернуть файлы из копии (существующие файлы не удаляются, недостающие — докачиваются):

```
set -a; . /etc/ikr-supabase/backup.env; set +a
rclone copy backup:ikr-backup/files files:ikr-files
```

## Проверить копии без восстановления

Раз в квартал стоит убедиться, что копии открываются. Это не трогает рабочую базу: копия разворачивается
во временную базу, проверяется и удаляется.

```
cat > /root/backup-key.txt          # вставить ключ, Enter, Ctrl+D
bash /opt/ikr-supabase/scripts/restore-check.sh /root/backup-key.txt
shred -u /root/backup-key.txt
```

Должно быть написано `ПРОВЕРКА ПРОЙДЕНА`.

## Что проверено

На проверочном стенде (как новая машина Ubuntu 24.04, хранилище — эмулятор S3), 13.10.2026:
- случай А: удалены все кандидаты → восстановление → кандидаты на месте, все 22 сценария сайта проходят;
- случай Б: стенд стёрт вместе с ключами, установлен заново с новыми ключами, база восстановлена из
  прежней копии → пользователи входят со своими паролями, все 22 сценария проходят;
- копия, снятая во время записи в базу, восстанавливается без расхождений.

На настоящей машине Selectel восстановление ещё не запускалось — его стоит проверить сразу после установки.
